# קלמנטינה

React + TypeScript + Supabase. אפליקציה בעברית ליומן אכילה ומעקב הרגלים, לשימוש אישי או עם שותפה.

## מבנה הפרויקט ועבודה על הקוד

זוהי אפליקציה אחת ומאגר אחד. גרסאות נשמרות בקומיטים של Git, ולא בעותקים של תיקיות או בקובצי עיצוב של גרסאות קודמות.

```text
src/
  App.tsx          חיבור המסכים, מצב החשבון ושמירת הנתונים
  components/      מסגרת האפליקציה ורכיבים משותפים
  features/
    auth/          התחברות ויצירת אתגר
    daily/         מסך היום וההרגלים
    food/          יומן אכילה ותכנון ארוחות
    progress/      גרפים, משקל ואנרגיה
    settings/      פרופיל, יעדים וגיבוי
    together/      שותפה והודעות
  lib/             עזרי תצוגה משותפים
  styles/
    index.css      נקודת הכניסה היחידה לעיצוב
    tokens.css     צבעים וגופנים
    app.css        רכיבים ופריסה, כולל התאמה לנייד
  data.ts          גישה לנתונים ו־Supabase
  domain.ts        טיפוסים, חישובים וכללי תקינות
  navigation.ts    לשוניות וכתובות המסכים
supabase/          מיגרציות ובדיקות הרשאות
tests/             בדיקות פריסה ובסיס הנתונים
```

לעדכון מסך עורכים את הרכיב הקיים בתיקיית התחום שלו. לעדכון עיצוב עורכים את הכלל הקיים ב־`app.css`, או את משתני העיצוב ב־`tokens.css`; אין להוסיף קובצי תיקונים כגון `clean`, `polish` או `v2`. כללי ההתאמה למסכים נמצאים בהמשך `app.css` לפי נקודות השבירה.

לפני קומיט מריצים:

```powershell
npm.cmd run format
npm.cmd run format:check
npm.cmd test
npm.cmd run build
```

קומיט הוא פעולה מקומית. `git push origin main` מעלה את הקומיטים ל־GitHub ומפעיל את הפריסה האוטומטית ב־Netlify כאשר היא מוגדרת. `dist/` ו־`node_modules/` נוצרים אוטומטית ואינם קובצי מקור; אין לערוך אותם או לצרף אותם לקומיט.

## הרצה מקומית

נדרש Node.js 22.12 ומעלה (נבדק עם Node 24). ב־PowerShell השתמשו ב־`npm.cmd` אם מדיניות ההרצה חוסמת את `npm.ps1`.

```powershell
npm.cmd install
npm.cmd run dev
```

בלי משתני סביבה, האפליקציה עולה במצב הדגמה המסומן בכל מסך. גם לאחר חיבור Supabase אפשר לפתוח את ההדגמה מכפתור במסך ההתחברות או בכתובת `http://127.0.0.1:5173/?demo=1`; מההדגמה אפשר לחזור לחשבון האמיתי. הדמו מכיל נתוני דוגמה של ״אני״ ו״אמא״ ושומר שינויים ב־localStorage בדפדפן הנוכחי. הוא אינו מסתנכרן בין מכשירים ואינו מועבר לחשבון. אפשר להחליף דמויות בהגדרות. ניקוי נתוני הדפדפן מוחק את הדמו. ניתן לייצא גיבוי JSON בהגדרות.

## חיבור Supabase

1. צרו פרויקט Supabase חדש.
2. בפרויקט חדש הריצו ב־SQL Editor, לפי הסדר, את `supabase/migrations/001_clementina.sql`, `supabase/migrations/002_food_entries.sql`, `supabase/migrations/003_optional_calories.sql` ואז `supabase/migrations/004_optional_amount.sql`. אם כבר הרצתם את המיגרציות הקודמות, הריצו רק את אלה שטרם הורצו. 004 מאפשרת לשמור ארוחה ללא כמות בחשבון האמיתי. עד להרצת 002 שאר האפליקציה ממשיכה לפעול, והיומן מציג הודעה שאינו זמין.
3. העתיקו `.env.example` אל `.env.local` והגדירו את Project URL ואת מפתח **Publishable** (או anon ציבורי). אין להשתמש במפתח secret או service_role בדפדפן.
4. ב־Authentication → URL Configuration הגדירו את Site URL לכתובת האפליקציה והוסיפו כתובות פיתוח, למשל `http://localhost:5173`, ל־Redirect URLs. הפעילו Email/password והרשמה עם אישור מייל. לשימוש שוטף, הגדירו SMTP שלכם.
5. הפעילו מחדש או בנו והעלו מחדש. משתני `VITE_` נקבעים בזמן הבנייה.
6. הראשונה נרשמת, מאשרת מייל ויוצרת אתגר. במסך ״ביחד״ → ״ההזמנה שלנו״ מעתיקים את קוד ההזמנה.
7. השנייה נרשמת בחשבון נפרד ובוחרת ״יש לי קוד הזמנה״. יש מקום לשתי חברות בלבד.

נתוני ההדגמה לא מיובאים לחשבונות אמיתיים. המשקלים בהדגמה מומצאים. האפליקציה אינה קובעת יעדים רפואיים.

## פריסה ב־Netlify דרך GitHub

ההגדרות מוכנות ב־`netlify.toml`. כתובת הפרויקט שנמסרה היא `https://ikvhhktviorkubyytmzn.supabase.co`.

1. קוד האפליקציה נמצא במאגר הציבורי [`Rivka387/clementina`](https://github.com/Rivka387/clementina), כשהאפליקציה בשורש המאגר. קובצי `.env.local`, `node_modules` ו־`dist` אינם נכללים בו.
2. ב־Netlify בחרו **Add new project → Import an existing project → GitHub**, ובחרו ב־`Rivka387/clementina`. השאירו את Base directory ריק.
3. הקובץ מגדיר אוטומטית Node 24, פקודת בנייה `npm run build:cloud` ותיקיית פרסום `dist`.
4. ב־Environment variables הוסיפו `VITE_SUPABASE_PUBLISHABLE_KEY`, עם ערך מ־Supabase → Settings → API Keys. נדרש שיהיה זמין בזמן Build בהקשר Production. הכתובת `VITE_SUPABASE_URL` כבר מוגדרת בקובץ Netlify.
5. לפני שימוש אמיתי, הריצו את מיגרציית Supabase לפי ההוראות למעלה.
6. לאחר קבלת כתובת Netlify, הגדירו אותה כ־Site URL וב־Redirect URLs ב־Supabase → Authentication → URL Configuration. אם משתמשים גם בכתובות Preview, יש לאשר אותן במפורש.
7. בצעו פריסה והירשמו בשני חשבונות נפרדים לצורך בדיקת הצטרפות, דיווחים ופרטיות המשקל.

בדיקת `build:cloud` מונעת פריסה לא מכוונת במצב דמו, ודוחה מחרוזת PostgreSQL או מפתח עם הרשאות מוגברות. היא בודקת את פורמט ההגדרות בלבד; אינה מחליפה בדיקת התחברות וסנכרון. Netlify מארח את הממשק; Supabase שומר את הנתונים ומאמת משתמשות. הגדרות הפריסה נמצאות ב־`netlify.toml`.

מקורות: [Vite on Netlify](https://docs.netlify.com/build/frameworks/framework-setup-guides/vite/), [Supabase API keys](https://supabase.com/docs/guides/getting-started/api-keys).

## התכולה

- במסך ״היום״ כרטיס יומן האכילה מציג סיכום קצר. לוחצים ״פתיחת היומן״ או ״רישום ארוחה״ כדי לפתוח מגירה, לרשום סוג, שעה ומה נאכל או נשתה; כמות וקלוריות הן רשות. אפשר לערוך או למחוק רישומים. סוגרים בכפתור הסגירה או במקש Escape. במסך ״התקדמות״ בוחרים יום מתוך השבוע וחוזרים לרישומים שלו.
- דיווח ארבעה הרגלים, מים, הליכה, אנרגיה ופתק יומי; עריכת ימים קודמים מתחילת האתגר.
- יומן אכילה אישי לפי שעה וסוג: מה נאכל או נשתה, עם כמות, קלוריות והערה לפי בחירה. אפשר להוסיף, לערוך ולמחוק רישומים; לא מוצג סכום יומי כאשר חלק מהרישומים ללא קלוריות. בפרק ההתקדמות יש סקירה של שבעה ימים עם קישור חזרה לכל יום.
- תכנון ארוחות אישי לבוקר, צהריים, ערב ונשנושים, עם מקום להנחיות שמתאימות לך. התכנון נשאר פרטי וניתן לעריכה; האפליקציה אינה יוצרת תפריט רפואי אוטומטי.
- אתגר 8, 12, 16 או 24 שבועות בחיבור חי; הדגמה של 12 שבועות.
- סיכומי 7/14/28 ימים, מבט שבועי על אנרגיה, רצף ימים עם לפחות הרגל אחד ומעקב משקל.
- משקל פרטי כברירת מחדל; שיתוף נבחר לכל מדידה. שמירה חוזרת לאותו תאריך מעדכנת את המדידה והשיתוף.
- פתקים משותפים וסטטוס השותפה; בענן רענון כל 20 שניות ובחזרה לחלון.
- יעדים ושמות אישיים, גיבוי JSON, RTL, התאמה לנייד, מקלדת והפחתת תנועה.

## אמינות ופרטיות

RLS נאכף בבסיס הנתונים: כל אחת עורכת רק את הדיווחים שלה; החברות באותו אתגר רואות הרגלים ופתקים; יומן האכילה ותכנון הארוחות נגישים רק לכותבת שלהם, ומשקל של שותפה נגיש רק כאשר שותף במפורש. עדכון פרופיל לא מאפשר לשנות מזהה משתמש או שיוך לאתגר. הצטרפות אטומית עם נעילת שורה מונעת כניסת משתמשת שלישית. קוד ההזמנה אקראי ואינו חשוף מחוץ לאתגר.

״נשמר״ מופיע רק אחרי אישור localStorage או Supabase. בכשל בענן מופיעה הודעה ונדרש ניסיון חוזר; אין תור כתיבה אופליין. אין מיזוג עריכות מקבילות של אותו חשבון משני מכשירים: השמירה האחרונה לאותו יום קובעת. שינוי יעד משפיע גם על חישובי העבר. תאריכים לפי Asia/Jerusalem. אין push או זמינות אופליין מובטחת. Google Fonts נטענים עם fallback מקומי.

## בדיקות ובנייה

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

הבדיקות מכסות גבולות יום, כפילויות, הפרדה בין משתמשות, יומן אכילה, ספי הרגלים, רצפים, שימור נתונים, כשלי אחסון והגדרות פריסה. בדיקת PostgreSQL באמצעות PGlite מריצה את ארבע המיגרציות ואת `supabase/tests/security.sql`, עם תפקידי anon/authenticated ומימוש מקומי של auth.uid(). היא מאמתת הרשאות וגילוי נתונים בטרנזקציה עם rollback. אותו SQL ניתן להרצה בפרויקט Supabase לבדיקות אחרי המיגרציה. PGlite הוא תלות פיתוח בלבד. בדיקת מיילים, התחברות וסנכרון אמיתיים עדיין דורשת פרויקט Supabase פעיל.

## עיצוב

הממשק מבוסס על רקע בהיר, כרטיסים לבנים, צבע טורקיז וטקסטים קצרים, בהשראת FinTrack. הרכיבים תומכים ב־RTL, ניווט מקלדת, תצוגת נייד והפחתת תנועה. האייקונים הם Lucide; הטקסט משתמש ב־Assistant והכותרות ב־Heebo, עם גופני גיבוי מקומיים.
