# קלמנטינה

**דברים טובים מבשילים ביחד.** React + TypeScript + Supabase. אפליקציה בעברית לאתגר הרגלים זוגי.

## הרצה מקומית

נדרש Node.js 22.12 ומעלה (נבדק עם Node 24). ב־PowerShell השתמשו ב־`npm.cmd` אם מדיניות ההרצה חוסמת את `npm.ps1`.

```powershell
npm.cmd install
npm.cmd run dev
```

בלי משתני סביבה, האפליקציה עולה במצב הדגמה המסומן בכל מסך. הדמו מכיל נתוני דוגמה של ״אני״ ו״אמא״ ושומר שינויים ב־localStorage בדפדפן הנוכחי. הוא אינו מסתנכרן בין מכשירים. אפשר להחליף דמויות בהגדרות. ניקוי נתוני הדפדפן מוחק את הדמו. ניתן לייצא גיבוי JSON בהגדרות.

## חיבור Supabase

1. צרו פרויקט Supabase חדש.
2. הריצו ב־SQL Editor את `supabase/migrations/001_clementina.sql` פעם אחת.
3. העתיקו `.env.example` אל `.env.local` והגדירו את Project URL ואת מפתח **Publishable** (או anon ציבורי). אין להשתמש במפתח secret או service_role בדפדפן.
4. ב־Authentication → URL Configuration הגדירו את Site URL לכתובת האפליקציה והוסיפו כתובות פיתוח, למשל `http://localhost:5173`, ל־Redirect URLs. הפעילו Email/password והרשמה עם אישור מייל. לשימוש שוטף, הגדירו SMTP שלכם.
5. הפעילו מחדש או בנו והעלו מחדש. משתני `VITE_` נקבעים בזמן הבנייה.
6. הראשונה נרשמת, מאשרת מייל ויוצרת אתגר. במסך ״שתיים זה ביחד״ → ״ההזמנה שלנו״ מעתיקים את קוד ההזמנה.
7. השנייה נרשמת בחשבון נפרד ובוחרת ״יש לי קוד הזמנה״. יש מקום לשתי חברות בלבד.

נתוני ההדגמה לא מיובאים לחשבונות אמיתיים. המשקלים בהדגמה מומצאים. האפליקציה אינה קובעת יעדים רפואיים.

## התכולה

- דיווח ארבעה הרגלים, מים, הליכה, אנרגיה ופתק יומי; עריכת ימים קודמים מתחילת האתגר.
- אתגר 8, 12, 16 או 24 שבועות בחיבור חי; הדגמה של 12 שבועות.
- סיכומי 7/14/28 ימים, רצף ימים עם לפחות הרגל אחד ומעקב משקל.
- משקל פרטי כברירת מחדל; שיתוף נבחר לכל מדידה. שמירה חוזרת לאותו תאריך מעדכנת את המדידה והשיתוף.
- פתקים משותפים וסטטוס השותפה; בענן רענון כל 20 שניות ובחזרה לחלון.
- יעדים ושמות אישיים, גיבוי JSON, RTL, התאמה לנייד, מקלדת והפחתת תנועה.

## אמינות ופרטיות

RLS נאכף בבסיס הנתונים: כל אחת עורכת רק את הדיווחים שלה; החברות באותו אתגר רואות הרגלים ופתקים; משקל של שותפה נגיש רק כאשר שותף במפורש. עדכון פרופיל לא מאפשר לשנות מזהה משתמש או שיוך לאתגר. הצטרפות אטומית עם נעילת שורה מונעת כניסת משתמשת שלישית. קוד ההזמנה אקראי ואינו חשוף מחוץ לאתגר.

״נשמר״ מופיע רק אחרי אישור localStorage או Supabase. בכשל בענן מופיעה הודעה ונדרש ניסיון חוזר; אין תור כתיבה אופליין. אין מיזוג עריכות מקבילות של אותו חשבון משני מכשירים: השמירה האחרונה לאותו יום קובעת. שינוי יעד משפיע גם על חישובי העבר. תאריכים לפי Asia/Jerusalem. אין push או זמינות אופליין מובטחת. Google Fonts נטענים עם fallback מקומי.

## בדיקות ובנייה

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

13 בדיקות מכסות גבולות יום, כפילויות, הפרדה בין משתמשות, ספי הרגלים, רצפים, שימור נתונים וכשלי אחסון. בדיקת PostgreSQL באמצעות PGlite מריצה את המיגרציה ואת `supabase/tests/security.sql`, עם תפקידי anon/authenticated ומימוש מקומי של auth.uid(). היא מאמתת הרשאות וגילוי נתונים בטרנזקציה עם rollback. אותו SQL ניתן להרצה בפרויקט Supabase לבדיקות אחרי המיגרציה. PGlite הוא תלות פיתוח בלבד. בדיקת מיילים, התחברות וסנכרון אמיתיים עדיין דורשת פרויקט Supabase פעיל.
